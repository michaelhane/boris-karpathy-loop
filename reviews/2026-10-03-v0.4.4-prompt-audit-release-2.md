# Review: v0.4.4 prompt-audit release 2

Tests: 21/21 pass (re-run).

## Findings

### [CONCERN] Pathspec is cwd-relative; scopeFiles origin is root-relative
- **Principle:** 3
- **Where:** workflows/workflow-review.js:141-145
- **Why it matters:** `git diff ... -- "path"` resolves paths against the agent's cwd. The paths in `scopeFiles` come from `git status --short` / `--name-only`, which are repo-root-relative. If a reviewer subagent runs from a subdirectory (consuming project, monorepo, worktree subfolder), the pathspec matches nothing and `diffCmd`/`numstatCmd`/`nameOnlyCmd` return empty. Before this change the same situation worked (unscoped). Nothing in the script treats an empty diff as an error, so the failure mode is a review that finds "nothing", indistinguishable from a clean change. This is a regression risk introduced for every scoped run.
- **Suggested resolution:** use the top-anchored magic (`:(top)path`) or document and assert the repo-root cwd assumption; make an empty diff under a non-empty scope a visible failure.

### [CONCERN] Paths are interpolated into a shell string with only double quotes
- **Principle:** 1
- **Where:** workflows/workflow-review.js:144
- **Why it matters:** quoting handles spaces, but not `"`, `$`, or backticks in file names, which the shell inside double quotes still expands. The command is embedded in prompts the agents run via Bash. Low probability, but the quoting is presented as the safe path and is not. The new tests cover only plain names, so the quoting choice is unexercised for the cases it exists for (spaces).
- **Suggested resolution:** escape or reject such characters, or state the limitation in a comment; add a test with a space in a path.

### [NIT] README still describes check 1 as "stale process state"
- **Principle:** 3
- **Where:** README.md:89
- **Why it matters:** the description of /diagnose-loop now disagrees with the command. The graphify report also still carries the old title; it will refresh on the next update.
- **Suggested resolution:** align the README wording.

### [NIT] Generated file edited by hand, regen unverified
- **Principle:** 4
- **Where:** skills/boris-cherny-way/SKILL.md, scripts/regen_skill.py
- **Why it matters:** the two edits are identical in the diff I read, which is good, but byte-equality after a real regen is unproven (KB submodule absent, stated by the author). Drift is only caught at the next regen.
- **Suggested resolution:** note it as a follow-up check on first regen (see verification_needed).

### [NIT] The wiring of the new helper is untested
- **Principle:** 4
- **Where:** workflows/workflow-review.js:65-67, tests/test_workflow_review.js
- **Why it matters:** the tests cover the pure function, not that the three top-level constants call it with the right flag, nor the hoisting claim (call site above the PURE block). The comment asserts hoisting is fine, which is correct for a top-level function declaration, but the project notes say the first live launch is the runtime gate, and no live scoped run is recorded in this diff.
- **Suggested resolution:** record one live scoped run as the acceptance evidence.
