# Review: v0.4.3 prompt-audit fixes

## Context
Applies hunks #1-#11 of prompt-audit-2026-10-02.md: text cleanups in CLAUDE.md, reviewer/tutor agents and three commands, plus a behavior change in workflows/workflow-review.js. The synthesizer now returns `{reviewPath}` via SYNTH_SCHEMA and the chat summary is built in code by the pure `buildSummary()`. Version bumped 0.4.2 -> 0.4.3.

## Findings

### [CONCERN] reviewPath is trusted, never verified, and the no-artifact branch is untested
- **Principle:** 4 (and 1)
- **Where:** workflows/workflow-review.js:354-363
- **Why it matters:** The old path made the model echo a path in prose; the new one only checks that a non-empty string came back. A hallucinated or mistyped path still yields a confident "workflow-review: <path>" summary with correct-looking counts, so a missing artifact is reported as success. Only `buildSummary` is covered by tests; the `error: 'no-artifact'` branch and the SYNTH_SCHEMA wiring sit outside the PURE fence and have never run. The counts in the summary come from code while the file/_index.md line are model-written, so the summary can disagree with the artifact (pre-existing, but now explicitly decoupled).
- **Suggested resolution:** Cheaply check the path exists (e.g. have the script or a tiny verify step confirm the file) before building the summary, or at least run one live /workflow-review and record it as the gate.

### [CONCERN] Error-path return shape is inconsistent with the success shape
- **Principle:** 1
- **Where:** workflows/workflow-review.js:357-362 vs :365; commands/workflow-review.md:40
- **Why it matters:** commands/workflow-review.md step 5 says "print the `summary` it returns". That still works literally, because the error return also carries `summary`, so the command does not break. But the error return omits `strategy`/`shards`, and step 5 never mentions `error`; the caller prints a "synthesizer did not report" line indistinguishable in handling from success. The command doc was not updated and does not tell the caller to treat `error` as a failure.
- **Suggested resolution:** One sentence in step 5: if `error` is set, say the review may be missing and point at `reviews/`.

### [NIT] Pointer to evidence file dropped from CLAUDE.md
- **Principle:** 3
- **Where:** CLAUDE.md:17
- **Why it matters:** The deleted line named `reviews/2026-06-11-dod-close-prd-fire-test.md` and the first opt-in commit. The replacement says "evidence in the COMMIT_PLAN DoD-close"; that file still exists, but the direct path is lost. Acceptable as history trimming; flagging it as an intentional loss.
- **Suggested resolution:** None required; keep if deliberate.

### [NIT] Removed duplicate bump bullet relies on the earlier bullet
- **Principle:** 3
- **Where:** CLAUDE.md (workflow-review section, tail)
- **Why it matters:** Verified the same rule remains in the review-gate section, so nothing is lost, but a reader of only the /workflow-review section no longer sees it.
- **Suggested resolution:** None.

### [NIT] "rough figures from 2026-05" adds a date in a change meant to be undated-safe
- **Principle:** 1
- **Where:** commands/setup-graphify.md:57
- **Why it matters:** The date is a claim the agent could not verify here; the old figures carried no stated origin. Mild, but it contradicts the stated "undated-safe" goal, and the figures still age.
- **Suggested resolution:** Say "rough, check current pricing" without a date, or confirm the date from the audit.
